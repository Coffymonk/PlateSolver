1. What PlateSolver does

PlateSolver takes an astronomical image (FITS, PixInsight XISF, TIFF, JPG, PNG or iPhone HEIC) and works out exactly which part of the sky it shows. This is called plate solving. It then finds the galaxies, nebulae, star clusters and bright stars in the picture and shows them:

  • as labels and outlines on the image, with each object's catalogued size and orientation,
  • in a list in the sidebar with each object's distance from Earth in light-years (you choose the number of decimals) and its true size,
  • with links: double-click an object to open its Wikipedia article (in the language you choose) or its page in the SIMBAD astronomical database.

Hovering the mouse over an object shows an information card: distance, size in light-years and when the light in your picture left it. Extra overlays add a coordinate grid, constellation figures and a north/east compass. The annotated picture can be exported for sharing, and a whole folder of images can be solved in one go.

How it works

The work happens in stages. Each stage is handled by one or more modules, which you can switch on and off and configure in Settings:

2. Installing and starting

Starting the program

  1. PlateSolver needs Python 3.10 or newer (from python.org; tick "Add python.exe to PATH" when installing).
  2. Double-click run.bat in the PlateSolver folder. The first start creates a private Python environment in the .venv folder and downloads the libraries it needs. This takes a few minutes and needs internet. Later starts take a few seconds.
  3. If the window doesn't appear, run run.bat debug from a command prompt. A console window then stays open and shows any error messages.

When a new version adds libraries, run.bat notices the changed requirements.txt and installs them automatically on the next start.

Stand-alone apps (Windows, macOS, Linux)

PlateSolver can also be packaged as an app that runs without Python: PlateSolver.exe (with an optional installer) on Windows, PlateSolver.app on macOS, and a folder or .tar.gz on Linux. The build folder contains a script for each system; see build/README.md. Each app has to be built on its own system, or all three at once with the GitHub workflow included in the project. Every build ends with a self-test of the finished app (PlateSolver --selftest report.txt), which checks that all modules, catalogues, the quiz and the manual are inside. The apps are not code-signed, so Windows and macOS show a warning the first time (Windows: More info › Run anyway; macOS: right-click › Open). ASTAP is installed separately in either case; the install helper makes that easy.

ASTAP (recommended, local solver)

ASTAP is a free, fast plate solver by Han Kleijn that runs on your own computer, without internet. It is separate software with its own licence, so it is not included in PlateSolver: install it with the install helper below, or yourself from hnsky.org/astap.htm. You need two things:

  • the ASTAP program, normally into C:\Program Files\astap, and
  • at least one star database. D50 suits most telescope images (fields from about 0.2° to 10°). Choose D20 or D05 for small downloads. For camera lenses and smartphone photos you also need W08 (or G05). The profile checklist shows whether the database you need is installed.

A star database is many files named like d50_0101.1476 in the ASTAP folder. You may also keep them in a folder called Database or databases inside the ASTAP folder: PlateSolver finds them there by itself and tells ASTAP where they are. On macOS the database installers put the files in /usr/local/opt/astap, not inside ASTAP.app, and on Linux the packages use /opt/astap (or /usr/share/astap/data); PlateSolver looks there too. (To see that folder in Finder, press Cmd+Shift+G and type the path.) Anywhere else, set Star database folder. Keep all databases in one folder, because ASTAP is given only one. PlateSolver finds ASTAP automatically; you can check or change its location in Settings › Plate solvers › ASTAP. The page shows a green tick and the databases found.

The ASTAP install helper

Tools › Install ASTAP and star databases… (also the first button in Settings › Plate solvers › ASTAP) shows what is installed and helps you download the rest. If ASTAP isn't found when PlateSolver starts for the first time, it offers this once; after a failed solve it is offered again (once per session) when the program or a star database is missing.

  • Disclaimer. At the top, the window explains that ASTAP and its star databases are third-party software, downloaded from ASTAP's own site (SourceForge, linked from hnsky.org) and installed by their own installers under their own licence terms, and that ASTAP also needs a star database, which is a separate download. Tick I understand… to enable the download buttons; the tick is remembered.
  • 1 ASTAP program. Shows ✓ and the path when ASTAP is installed, otherwise ✗. Download and install ASTAP downloads the official installer for your system (Windows .exe, macOS .pkg for Apple silicon or Intel, Linux .deb or .rpm) and starts it. Follow the installer's steps and keep the suggested folder. Where there is no single installer (32-bit Windows, other Linux systems) ASTAP's download page opens instead. When ASTAP is already installed, the same button installs the newest version.
  • 2 Star database (can be done later). The databases are optional and separate: you can install only the program now and come back for a database later. The list shows every database with its use and approximate download size; the one that suits your profile comes first, marked recommended (W08 for phones, W08 and D50 for camera lenses, D50 or D80 for telescopes depending on the field size), and installed ones are marked installed. On Windows and macOS the database comes with its own installer; on Linux as a package, or as a zip file that PlateSolver unpacks into the ASTAP folder (or its own data folder, which it then sets as Star database folder).
  • Downloads are saved in your Downloads folder, so you can find an installer and run it again later.
  • More than one database on a Mac. Some of ASTAP's Mac database installers share an internal name: the D50 installer uses the same one as D05, and G05 the same one as V50. macOS then treats installing the second as an update of the first and removes the first database's files, so the two keep replacing each other. Before starting a database installer, the helper reads its internal name and checks whether macOS would remove another database. If so, it explains and offers Protect and install: it tells macOS to forget the earlier install (macOS asks for your password; no files are deleted), then starts the installer, so both databases stay. Install anyway skips this. If you install outside PlateSolver, do the same by hand in Terminal before installing the next database: pkgutil --pkgs lists the names, sudo pkgutil --forget d05 forgets one. If a database disappears after an install anyway, the helper says so after Check again; install it again to get it back.
  • Progress and Cancel. Large databases (D50 is about 900 MB, D80 about 1.2 GB) can take a while; the bar shows how far it has come.
  • Check again. Press it after an installer has finished. PlateSolver then finds the new ASTAP and its databases and fills in ASTAP program in Settings if it was empty or wrong. A location you have set yourself is never replaced while it still works.
  • If a download fails (no internet, a firewall, or the download site has changed), ASTAP's download page opens, so you can download it there by hand.

astrometry.net (optional, online solver)

astrometry.net can solve almost any image, even with no information at all, but it is slower (usually 1–5 minutes) and needs internet. PlateSolver only uses it when ASTAP is missing or fails. To enable it:

  1. Create a free account at nova.astrometry.net.
  2. Open My Profile there and copy your API key.
  3. Paste it into Settings › Plate solvers › astrometry.net (online).

Before anything is uploaded, PlateSolver asks you. The question says exactly what will be sent:

  • a reduced monochrome copy, at most 2000 pixels on the longest side,
  • without the file's information (no date, camera, location or object name); only a rough position and image scale are sent, to speed up solving (switch off with Send position and scale hints),
  • stored privately in your astrometry.net account (not publicly visible).

Answer Upload or Don't upload. Tick Remember my answer until PlateSolver is closed to avoid being asked for every image in a batch. To never be asked, switch off Ask before uploading an image in the astrometry.net settings. To never upload at all, leave the API key empty.

astrometry.net keeps uploaded images in your account; there is no automatic deletion and the service offers no way for programs to delete them. The submission number is shown in the Log tab if you want to ask the site's administrators to remove one.

3. Quick start

  1. Set up a profile for your equipment once: Tools › Profiles… (Ctrl+P), pick a template (for example Astro camera on a telescope), click Make my own profile from this template, choose your camera and enter the focal length. The window shows the resulting image scale (350 mm and 2.9 µm give 1.71″ per pixel) and a checklist of anything else that is still needed, such as a star database. See Equipment profiles, and which profile for which equipment if you're unsure.
  2. Choose the profile in the toolbar (Profile:). For phone photos, pick a smartphone profile.
  3. Open an image: Ctrl+O, the Open button, or drag a file onto the window.
  4. Press Solve (F5). If only part of the image shows sky, crop it first (C). The status bar shows the centre coordinates when done. To solve every image as soon as it opens, switch on Solve automatically when an image is opened in Settings › General.
  5. The Objects tab lists what is in the picture, with distances. Point at an object on the image for its information card; double-click it to read about it.
  6. Export the annotated picture with Ctrl+E.

4. Cameras, lenses and telescopes explained

This chapter explains the equipment that takes astronomy pictures – phones, cameras, lenses and telescopes – in plain words, and what each means for PlateSolver: which profile to choose and which numbers to fill in. You don't need any of it to get started, but it helps when an image won't solve or you set up your own equipment.

The one thing PlateSolver needs to know: how much sky one pixel covers

To recognise the stars, PlateSolver (and ASTAP behind it) must know roughly how big the stars' pattern is in your picture. That is the image scale: how much sky one pixel covers, in arc-seconds per pixel (″/px). It depends on just two things:

  • The focal length of the lens or telescope, in millimetres. A longer focal length magnifies more, so each pixel covers less sky.
  • The pixel size of the camera's sensor, in micrometres (µm). Bigger pixels each cover more sky.

Image scale (″/px) = 206.3 × pixel size (µm) ÷ focal length (mm). Example: 2.9 µm pixels behind a 350 mm telescope give 206.3 × 2.9 ÷ 350 = 1.71″ per pixel. Multiply by the number of pixels to get the field of view: 1.71″ × 2160 pixels = 3,700″ ≈ 1.0° high.

For comparison: the full Moon is about 0.5° (1,800″) across. A telescope image typically covers 0.3–3°, a camera lens 10–60°, and a phone photo 50–110° of sky.

Everything else – brand, colour or mono, cooled or not, the size of the front lens or mirror (aperture) and the f-number – does not change the image scale. Those matter for how faint you can reach and how long you expose, not for plate solving.

Imaging devices

Smartphones

A phone has several small cameras: usually a main camera, an ultra-wide (shown as 0.5×) and sometimes a telephoto (2×, 3×, 5×). Their tiny lenses have real focal lengths of only a few millimetres, so phones describe them as a 35 mm-equivalent focal length instead: the lens on a classic full-frame camera that would show the same view. The main camera is typically 24–26 mm equivalent, the ultra-wide 13 mm, telephotos 48–120 mm.

  • Profile: Smartphone, main camera (26 mm) or Smartphone, ultra-wide (13 mm). For an iPhone 14 Pro or newer, make your own profile from the main-camera template and set Lens for photos without EXIF to 24 mm.
  • Star database: W08 (fields wider than about 10°).
  • The original photo contains EXIF information (camera model and lens) that PlateSolver reads by itself. Copies sent through messaging apps or exported from editors often lose it; the profile then supplies the lens.
  • Phone photos are wide and their lenses bend straight lines near the edges. PlateSolver corrects this lens distortion by itself, and offers the phone and wide-field aids when a photo won't solve. Night modes that stack and sharpen many frames are fine.

DSLR and mirrorless cameras

Both are "system cameras" with interchangeable lenses. A DSLR (digital single-lens reflex) has a mirror inside that reflects the view up into an optical viewfinder and flips out of the way when the picture is taken. A mirrorless camera has no mirror: the sensor is always exposed and you look at an electronic viewfinder or the screen. For astronomy and for PlateSolver they behave the same – what matters is the sensor and the lens or telescope in front of it.

  • Sensor size. Full frame is 36 × 24 mm (Canon R, Nikon Z, Sony A7 and similar). APS-C is about 23.5 × 15.6 mm (the "crop factor" is 1.5, or 1.6 for Canon). Micro Four Thirds is 17.3 × 13 mm (crop factor 2). A smaller sensor with the same lens shows a smaller piece of sky.
  • With a camera lens: profile DSLR / mirrorless with a camera lens. Each photo's EXIF tells PlateSolver the focal length and camera, even when you zoom, so there is usually nothing to fill in. For old manual lenses that leave no EXIF, set Lens for photos without EXIF.
  • On a telescope (the camera body attached with a T-ring, without its lens): profile DSLR / mirrorless on a telescope. Pick the camera body (it fills in the pixel size) and enter the telescope's focal length – the camera can't know it.
  • "Astro-modified" cameras (with the infrared filter removed or replaced) solve exactly like unmodified ones.

Dedicated astronomy cameras

Cameras made for telescopes – ZWO (ASI), QHY, Player One, ToupTek, Atik, Moravian and others – have no lens, viewfinder or screen; they are controlled from a computer or a control box such as the ASIAIR. Many are cooled to reduce noise. Colour cameras record red, green and blue in one go; mono cameras record one filter at a time (L, R, G, B, Hα, OIII, SII), and the colour image is combined later.

  • Profile: Astro camera on a telescope. Pick your camera (it fills in the pixel size and sensor size) and enter the telescope's focal length.
  • The FITS files that capture programs (N.I.N.A., ASIAIR, SharpCap, APT, Ekos …) save usually contain the focal length and pixel size, and often the pointing position, in their header. PlateSolver uses those first, so FITS files solve quickly even with a different profile.
  • Processed results (TIFF, JPG, PNG) usually lose that information; then the profile is what counts.

Smart telescopes

All-in-one instruments (for example from ZWO, Vaonis, Unistellar or DWARFLAB) contain a small telescope, camera and computer in one unit and plate solve by themselves while observing. Their FITS files often already contain the solution, which PlateSolver then uses directly (Existing solution in file). For their JPG or PNG results, make an Astro camera on a telescope profile with the focal length and pixel size from the maker's specifications.

Optics: lenses and telescopes

Camera lenses

A lens is described by its focal length and its widest aperture as an f-number, for example 50 mm f/1.8. Only the focal length matters for PlateSolver. Zoom lenses (e.g. 18–55 mm) record the focal length actually used in the EXIF. Wide-angle lenses (14–35 mm) show the Milky Way and whole constellations; short telephotos (85–200 mm) show large nebulae and star clusters.

Telescopes

A telescope is a lens or mirror system with a long focal length. Its aperture (the diameter of the main lens or mirror, e.g. 71 mm or 200 mm) decides how much light it collects; its focal length (e.g. 350 mm or 2000 mm) decides the image scale; the focal ratio f/ is focal length ÷ aperture (350 ÷ 71 ≈ f/4.9).

Reducers, flatteners and Barlow lenses

Extra optics between telescope and camera change the focal length. A focal reducer (e.g. 0.8× or 0.63×) shortens it: 1000 mm × 0.8 = 800 mm, a wider view. A Barlow lens (2×, 3×) lengthens it. A field flattener only straightens the field and leaves the focal length unchanged (×1.0). Always enter the effective focal length – the telescope's focal length times the reducer's or Barlow's factor. If you're unsure, solve one image and read the actual scale in the Solution tab (see below).

Binning, drizzle, cropping and resizing

  • Binning 2×2 combines four pixels into one: each pixel is twice as big, so the image scale doubles. Capture programs record this in FITS files.
  • Drizzle (in stacking programs) does the opposite: a 2× drizzled image has twice as many pixels and half the scale. PlateSolver recognises drizzled images by their size (Equipment › Recognise drizzled images by their size).
  • Cropping keeps the scale – it only removes the edges. Resizing changes it. When the scale is unknown or changed, ASTAP retries with any scale by itself.

When you don't know the focal length or pixel size

Leave them empty rather than guessing: a wrong scale is the most common reason an image won't solve. With nothing filled in, ASTAP tries image heights from about 10° down to 0.3°, which covers almost every telescope, and astrometry.net (if set up) can solve without any information. A hint helps a lot: Image › Solve with object hint and the object's name, e.g. M 31. After solving, the Solution tab shows the real image scale. If you know the pixel size, the focal length follows: focal length (mm) = 206.3 × pixel size (µm) ÷ scale (″/px). Make a profile with it, and the next images solve in seconds.

Photos of a screen or a print

Sometimes the only picture you have is a phone photo of a screen: a live view in ASIAIR, N.I.N.A., SharpCap or a smart-telescope app on a tablet or laptop, a friend's monitor, or a printout. The stars in such a photo were imaged through the telescope, but the photo's EXIF describes the phone, so a phone profile would tell the solver the field is 60–70° high when it is really a degree or less – and solving fails. Choose the template Photo of a screen or print (in the toolbar, or make your own from it in Tools › Profiles…). It:

  • ignores the photo's lens information and lets the solver find the scale itself (ASTAP's automatic scale). This is slower, so an object hint – Image › Solve with object hint with the object's name – helps most;
  • stays chosen: the phone's EXIF does not switch to a smartphone profile;
  • tries a softened copy of the photo if it doesn't solve as it is. This smooths moiré – the wavy pattern a camera picks up from screen pixels – and JPEG blocks; the phone aids are not used;
  • skips lens distortion correction: the stretch in such a photo comes from the viewing angle, not from a lens.

Height of the sky shown (optional): if you know how much sky the screen shows – for example from your telescope and camera (see image scale) – make your own profile and enter it in degrees. The solver then searches with that field instead of trying every scale. Measure the height of the star area only, as shown on the screen.

Tips: photograph the screen straight on and fill the frame with the star area; crop away menus, buttons and text before solving (they are not stars and confuse the solver) – PlateSolver's own Crop and rotate (C) does this without changing the photo; turn off the screen's night or red mode if you can; avoid reflections. The solution then applies to the cropped photo. Labels on a photo of a screen are positioned as well as the viewing angle allows, so they can be a little off near the edges.

Rotated, mirrored and upside-down images

Telescope images are almost never "north up": the camera's angle on the telescope decides how the picture is turned, and that's fine. Some setups also show the sky mirrored – as if seen in a mirror:

  • systems with one reflection, such as RASA and HyperStar, or a camera behind a star diagonal (normally used for looking through the eyepiece);
  • a phone's front (selfie) camera, or a phone held to an eyepiece with a diagonal;
  • a flip in a capture or editing program (Flip horizontal / Flip vertical), or software that reads a FITS file's rows in the opposite order. A vertical flip is the same as a horizontal flip turned half a turn: also mirrored.

PlateSolver handles all of these by itself – there is nothing to set. The solvers (ASTAP, astrometry.net) recognise the star pattern whether it is rotated or mirrored, and the solution records both. The Solution tab shows the rotation (Up = … ° E of N) and Mirrored: Yes/No; labels, the compass (N and E arrows), the grid, constellations, lens distortion correction and the visible-stars check all follow the solution, so they are correct on mirrored images too. In a mirrored image the compass shows east on the "wrong" side of north compared with a normal sky view – that is the sign that the picture is mirrored, not an error. PlateSolver shows your image exactly as the file stores it; if you prefer it the right way round, flip it in your image editor, and PlateSolver will solve the flipped copy just as well.

5. The main window

The image

  • Zoom with the mouse wheel (it zooms towards the mouse pointer), or Ctrl + / Ctrl −. F fits the image to the window, 1 shows it at 100 %.
  • Move the image by dragging it.
  • Crop and rotate (C) solves only part of the image, without changing the file. See Crop and rotate.
  • Point at an object to see its information card. Click an object to select it (it is circled in blue and highlighted in the list). Double-click it to open its Wikipedia or SIMBAD page. Right-click it for all links and copy options.
  • Double-clicking empty sky fits the image to the window.

Labels keep the same size on screen at every zoom level. In crowded fields, less prominent labels are hidden so they don't overlap; zoom in and they appear.

Crop and rotate

Sometimes only part of an image should be solved: the star area of a photo of a screen without the app's menus and text, a photo with a tree or a roof in it, or a stack with ragged, empty edges. Crop and rotate (toolbar, Image › Crop and rotate or C) changes the image shown in PlateSolver – your file is never changed.

  1. Click Crop and rotate. A bar appears above the image.
  2. Rotate first if it helps you line up the selection: the 90° buttons turn the image a quarter turn anticlockwise or clockwise ([ and ]), and Straighten turns it a little, up to 45° either way – for example to line up a photographed screen with the edges. New corners are filled with the sky colour.
  3. Drag a rectangle around the part you want. Drag inside it to move it, drag an edge or a corner to resize it, or drag outside it to start again. The size is shown at its corner; everything outside is darkened. The mouse wheel zooms, and the right mouse button moves the image while you select.
  4. Apply and solve (Enter) shows only the selection and plate solves it. Apply shows it without solving, Reset undoes the rotation and the selection, and Cancel (Esc) leaves everything as it was.

The edited view is then used like any image: solved, labelled, listed and exported. The Solution tab and the Log say that it is an edited view, and exports get _edited in their suggested file names. You can crop again to narrow it further. Original image in the toolbar (Image › Back to the original image, Shift+C) shows the whole image again; solve it again after that (F5).

  • Cropping and rotating don't change how much sky a pixel covers, so your profile and the image's own scale information still apply. Plate solvers find the stars at any angle, so rotating isn't needed for solving – it's only there to make the selection easier.
  • A plate solution stored in a FITS or XISF file no longer fits the edited pixels, so the edited view is solved again. For the same reason Write plate solution into this FITS file is not available for an edited view; a saved .wcs file describes the edited view.
  • A selection needs at least 32 × 32 pixels. Keep it as large as the unwanted parts allow: the more stars it holds, the easier it solves.

6. Opening images

FormatNotes
FITS (.fits, .fit, .fts)Mono, colour and raw one-shot-colour frames. Raw colour frames (with a BAYERPAT keyword) are shown in colour with a simple debayer. Pointing, focal length and pixel size are read from the usual header keywords (RA, DEC, OBJCTRA, OBJCTDEC, FOCALLEN, XPIXSZ, …). If the file is already plate solved, that solution is used immediately.
XISF (.xisf)PixInsight's own format: integer or floating-point, mono or colour, compressed or not. FITS keywords and PixInsight's metadata are read as solving hints: position (OBJCTRA/OBJCTDEC, the observation centre), focal length, pixel size and camera name (which can choose your profile automatically). A plate solution stored by PixInsight's ImageSolver is used as an exact position and scale hint, so the image is re-solved in seconds. Integration and drizzle outputs keep this information; an image created by PixelMath or other processes as a new image usually doesn't, but the file name (e.g. FINAL_PELICAN_IC5070.xisf) still gives an object hint. Opening an XISF is usually more reliable than solving the Photoshop JPG made from it.
TIFF (.tif, .tiff)8, 16 and 32-bit, as exported by stacking software. 16/32-bit TIFFs are treated as unstretched by default (see TIFF settings).
JPEG / PNG / HEICAlready-processed pictures, including iPhone photos in HEIC format. For camera and phone photos the image scale is worked out from the EXIF data (see Wide-field images). Photos sent through messaging apps usually lose their EXIF data and are shrunk and recompressed, which makes them much harder to solve: use the original file. For telescope images without EXIF, fill in Equipment.

Unstretched (linear) images

Data straight from the camera or a stacker looks almost black. PlateSolver brightens it for display with an automatic stretch; the original data is used for solving. The stretch strength is set in General.

Which way up?

The FITS standard stores the bottom row first, but some capture programs store the top row first and say so with the ROWORDER keyword. PlateSolver follows that keyword. If your images appear upside down compared with other software, change FITS › Row order. Solving and labels are always correct either way; only the display orientation changes. Mirrored and rotated images are explained in Rotated, mirrored and upside-down images.

7. Plate solving

Solving compares the pattern of stars in your image with a star catalogue. The result is a WCS (World Coordinate System): a formula that turns any pixel into sky coordinates and back. It gives the image centre, scale (arc-seconds per pixel), field of view, rotation and whether the image is mirrored.

Which solver is used

Solvers are tried in order until one succeeds:

  1. Existing solution in file: FITS files that were already plate solved (by PlateSolver, ASTAP, N.I.N.A., …) are used as they are. Instant.
  2. ASTAP: local and fast, usually a few seconds.
  3. astrometry.net: online, slower, but solves almost anything. Only used when it has an API key.

The Solution tab shows which solver succeeded, and what the others reported if they failed.

Hints make solving fast

A solver that knows roughly where to look and how large the field is finishes in seconds. Without hints it must search the whole sky ("blind solving"), which takes much longer.

  • Image scale comes from focal length × pixel size: scale [″/px] = 206.265 × pixel size [µm] ÷ focal length [mm]. It is read from the FITS header or a camera photo's EXIF data, or taken from your profile (Settings › Equipment) when the file doesn't say. Drizzled images are recognised by their size (see Drizzled images), and phone photos without EXIF use the profile's lens (see Wide-field images).
  • Position (RA/Dec) comes from the FITS header, written by the capture software from the mount's position, or from an object hint (the file name, or what you type).

After solving, PlateSolver compares the expected scale with the measured one. If they differ by more than 5 %, the Scale check line in the Solution tab explains where the wrong value came from. It also recognises typical causes such as 2×2 binning or a drizzled image.

Equipment profiles

A profile holds everything that depends on your camera: focal length, pixel size, sensor size, drizzle detection, the lens to assume for phone photos without EXIF, and the ASTAP field and database options. Pick a profile in the toolbar (Profile:) and all of these are set at once.

  • Templates to start from: Astro camera on a telescope, DSLR / mirrorless on a telescope, DSLR / mirrorless with a camera lens, Smartphone, main camera (26 mm), Smartphone, ultra-wide (13 mm) and Photo of a screen or print (see Photos of a screen or a print).
  • Your own profiles: Tools › Profiles… (Ctrl+P), choose a template, click Make my own profile from this template, give it a name (e.g. "Redcat 71 + ASI585MC Pro"), pick your camera and enter the focal length.
  • Camera list. Astro cameras are grouped by manufacturer: ZWO, Player One, QHYCCD, Svbony, Altair, Atik, Moravian and ToupTek, plus Other brand – by sensor for any camera with a known sensor (IMX585, IMX571, IMX533, …). Choosing a camera fills in its pixel size and resolution. DSLR/mirrorless bodies and phone lenses have their own lists. If your camera isn't listed, choose "none" and enter the values yourself.
  • Automatic choice. When an image is opened, its metadata can pick the profile: a FITS whose camera (INSTRUME) matches one of your profiles uses that profile; a photo with Apple, Samsung, Google … EXIF uses a smartphone profile; a camera photo with lens data uses a camera-lens profile. An image without any camera information uses the profile you chose in the toolbar, so an automatic switch never sticks. When you have chosen a Photo of a screen or print profile, no automatic switch is made: such photos carry the phone's EXIF. The Log says when the profile changes. Settings: Settings › Profiles.

Checklist. For each profile, the Profiles window shows Before you solve with this profile: what else is needed, checked against what is actually installed and set. ✓ means done, ⚠ means still needed, • is advice. For example: a telescope profile needs the focal length, the pixel size and a D50/D80 database; a smartphone profile needs ASTAP's W08 database, and for ultra-wide photos astrometry.net. Missing items are also written to the Log (Profile needs: …) when you pick a profile, and shown in the toolbar tooltip. The field of view height and star database are left on automatic by every profile, so you don't need to set them by hand.

Object hints: "this is M101"

JPG, PNG and most TIFF images, and XISF images that PixInsight created as new images (e.g. with PixelMath), don't say where in the sky they were taken, so the solver has to search the whole sky. If you know what the image shows, tell PlateSolver: the solver then only searches near that object, which is much faster and far more reliable.

  • From the file name. Catalogue names like M101_final.jpg, NGC7380_stars.tif, IC1396.jpg or Sh2-155.jpg, and common names from the built-in catalogue like crescent_final.jpg, North_America.tif or Andromeda.jpg, are recognised automatically. The Log says which object was assumed.
  • Image › Solve with object hint… (Shift+F5): type an object name (M101, NGC 7380, Pleiades, Wizard Nebula) or coordinates (14 03 12.6 +54 20 56, or 210.80 54.35 in degrees).
  • When solving fails, PlateSolver asks whether you know what the image shows.

Names are looked up in the built-in catalogue (Messier, NGC, IC and common names, offline) and otherwise in SIMBAD (online). The object doesn't have to be in the centre of the image.

Drizzled images. Drizzle integration (for example in PixInsight or Siril) makes the image 1.5, 2 or 3 times larger than the sensor, so each pixel covers that much less sky. Enter your camera's sensor width and height in Equipment (3840 × 2160 for an ASI585MC). An image clearly larger than the sensor is then treated as drizzled, and the scale is divided accordingly; the Solution tab says so.

Cropped and resized images. Cropping alone keeps the image scale (each pixel still covers the same patch of sky), and PlateSolver already accounts for the smaller image. But a crop that was then resized, a drizzled or binned stack, or an image taken with other equipment has a different scale from your Equipment settings. Near a hinted object, ASTAP therefore also tries any image scale, which is quick there. If the hint was wrong, the whole sky is searched as usual. astrometry.net gets a wide scale range (¼ to 4× the Equipment value) instead of a fixed one.

Settings: Settings › Object hints.

Starless images

Plate solving works by matching star patterns, so an image without stars cannot be solved. That includes starless versions made with StarNet or StarXTerminator. Before solving, PlateSolver therefore counts the stars in the image, which takes well under a second. Only compact points of light count: nebula detail is too broad and hot pixels are too sharp to be taken for stars.

  • The number found is shown in the Solution tab as Stars found.
  • If there are fewer than 15 (adjustable), a warning appears: Solve anyway tries all the solvers as usual, Don't solve stops straight away.
  • In batch mode nothing is asked: such images are listed as skipped (or tried anyway, if you turn that off).
  • Images that already contain a plate solution are not checked: they open solved regardless of stars.

Settings: Settings › Star check. Tip: solve the version of your image that still has its stars.

Non-flattened images, gradients and hot pixels

Some images have plenty of stars and still fail to solve. Common reasons:

  • no flat-field correction, leaving dark corners (vignetting) and dust donuts,
  • strong gradients from light pollution or the Moon,
  • no dark frames, leaving many hot pixels that look like stars to a solver.

PlateSolver can give the solvers a cleaned copy of the image instead. Its background is flattened, by dividing out a smooth background model like a synthetic flat, and isolated hot pixels are removed. Star positions stay exactly where they are, so the solution is valid for your original image. Your image and its display are never changed.

  • The Solution tab shows how much the background varies across the image. Above about 20 % it is marked as uneven.
  • In the default Automatic mode, a clearly uneven raw (unstretched) image is solved from the cleaned copy first, then as it is. A processed image (JPG, PNG, stretched TIFF or XISF) is always tried as it is first: a large nebula or galaxy can make it look uneven even though its background is fine. Otherwise ASTAP gets a second try with the cleaned copy if the first fails.
  • When the cleaned copy did the job, the Solution tab says so.

Settings: Settings › Solving aids. Calibrating with flats and darks (or a stacker that does) is still the best fix for your final images.

Wide-field and Milky Way images

Photos taken with a camera lens (14–135 mm) cover tens of degrees of sky. They usually contain hundreds of stars and are perfectly solvable, but they need different treatment from telescope images:

  • The right star database. ASTAP's D50 database is made for fields up to about 10°. For wider fields ASTAP needs W08 (or G05). Download it from hnsky.org/astap.htm and unpack it into the ASTAP folder. With Star database set to Automatic in Settings › ASTAP, PlateSolver then selects W08/G05 by itself for fields wider than about 10°. If it is missing, the Log says so when solving fails.
  • The scale comes from the camera. For JPGs and TIFFs, PlateSolver reads the focal length and sensor size from the camera's EXIF data (or the 35 mm-equivalent focal length). This is also correct after the picture was resized. Your Equipment values describe your telescope and are not mixed with a lens's focal length: a 24 mm lens with a 2.9 µm telescope camera's pixel size would give a scale 100 times too fine. When a value in the file doesn't match your equipment, the Solution tab says it was not combined.
  • No EXIF? Exported or edited JPGs (and photos saved by apps such as Picasa or sent through messaging apps) often lose it. Choose a smartphone profile: it assumes the phone's main camera (26 mm equivalent; use 24 mm in your own profile for an iPhone 14 Pro or newer). For a camera lens, set Lens without EXIF in your own camera-lens profile. As a last resort, enter the field height under ASTAP › Field of view height and set it back to 0 afterwards. ASTAP wants the height worked out from the scale at the centre of the image, which for wide lenses is larger than the true angle: about 57° for a 24 mm lens on full frame in landscape, about 76° for a phone's 26 mm main camera in portrait (57° in landscape).
  • Bright Milky Way. The glowing band is a strong, uneven background. The cleaned copy flattens it, so leave Solving aids on Automatic (or set Flatten to Always).
  • Lens distortion and very wide angles (fisheye, below about 14 mm) can still defeat solvers. The phone and wide-field aids then solve the less distorted centre of the photo. astrometry.net, which handles distortion well, is another option.

Phone photos that won't solve: phone and wide-field aids

A phone's very wide lens stretches the star patterns more and more towards the edges of the photo, so the patterns there no longer match the solver's catalogue. Phone photos also often have trees or houses along the bottom, a strong light-pollution gradient, noisy pixels and JPEG compression. When every normal attempt has failed, PlateSolver can make a last try with its phone and wide-field aids.

You are asked first. When a JPG, HEIC, PNG or TIFF image can't be solved, PlateSolver asks Was it taken with a mobile phone, or another camera with a very wide lens? If the camera information shows a phone (for example camera: Apple iPhone 13) or the file is a HEIC, the question says so. Answer Yes, try the phone aids to go ahead, or No to stop. Telescope images in FITS or XISF format are not asked about, unless their field is wider than 5°.

What the aids do, on a copy (your image is never changed):

  1. Foreground blacked out. Dark silhouettes (trees, buildings, hills) and lit, starless ground along the edges of the photo are found and painted over, so lights and branches are not mistaken for stars. Open sky, including the bright Milky Way, is left alone because it is full of stars.
  2. Cleaned up. The light-pollution gradient is flattened, hot pixels are removed and JPEG blocks are smoothed (more strongly for very compressed files, for example photos sent through a messaging app).
  3. Only the centre is solved. The centre of a phone photo is hardly distorted. By default the middle 50 % (in each direction) is tried first, then the middle 30 %. The expected field size is reduced to match, so the scale stays right.
  4. 2 × 2 pixels combined in large parts (over 2000 pixels) and in strongly compressed JPGs: clearer stars from noisy phone sensors, fewer false "stars" from JPEG blocks, and faster. Never below 600 pixels on the short side, since ASTAP needs enough pixels to work with.
  5. Mapped back. The solution of the centre is converted to the whole photo, so labels and the grid land in the right place everywhere.
  6. Refined. Now that the position and scale are known exactly, PlateSolver makes one quick try (about a second) on the whole photo, then on the middle 75 %. With strong lens distortion, as in most phone photos, these usually don't solve, and that's expected.
  7. Lens distortion corrected. Finally the stars in the whole photo are paired with PlateSolver's own star catalogue and the lens distortion is measured and taken into account, so the labels sit on their stars right out to the corners. See Labels on their stars: lens distortion. If that isn't possible (too few stars), the centre's solution is used as it is, and labels near the edges may be slightly off.

The Solution tab and the Log say which part solved, e.g. Solved with the phone and wide-field aids (…, middle 50 %, 2×2 pixels combined). The whole photo was then solved near that position.

Not only for phones. Processed telescope images that won't solve as a whole (for example a JPG whose star pattern was changed by stretching, star reduction or warping) can still solve from their centre. Answer Yes to the question for those too: in testing, a drizzled and processed JPG of the Crescent Nebula that no other attempt could solve was solved this way.

Why not rotate the image? Rotating by 90°, 180° or 270° does not help: the solvers compare star patterns in a way that doesn't depend on rotation (or mirroring), so a rotated photo fails for exactly the same reason.

Tips:

  • Install ASTAP's W08 star database: the centre of a phone photo is still 20–40° wide.
  • Choose a smartphone profile (or a camera-lens profile), so the expected scale is right.
  • Use the original photo from the phone. A copy sent through a messaging app or social media is resized and strongly compressed, which leaves few usable stars.
  • Night mode and long exposures help: more stars make solving easier.

Settings: Settings › Phone and wide-field aids. When nothing else solves the image can be Ask (default), Try automatically (also used in batch mode, where nobody is asked) or Never. You can also choose which parts are tried, and switch the foreground mask, the 2 × 2 binning and the refining step on or off.

Labels on their stars: lens distortion

A plate solution maps every pixel to a position in the sky using the model of an ideal lens, where straight lines stay straight. Real wide-angle lenses, and phone lenses in particular, bend the picture slightly, more and more towards the edges. Phones correct most of this before saving the photo, but 1–2 % usually remains: on a 12-megapixel photo that is 30–80 pixels in the corners. A solution found only from the centre of a photo (the phone aids) also carries tiny scale and rotation errors outwards. The result: labels sit right in the middle but drift off their stars towards the edges.

PlateSolver therefore checks wide-field solutions against its own star catalogue:

  1. It finds the stars in the photo (their centres to a fraction of a pixel).
  2. It pairs them with catalogue stars, starting in the centre, where the solution is right, and working outwards ring by ring, so each pairing is unambiguous even where the labels were far off.
  3. It fits the lens distortion with SIP polynomials, the FITS standard used by astrometry.net and professional observatories, and refits as more of the photo is covered.

The Solution tab and the Log then say, for example, Lens distortion corrected using 640 catalogue stars (accuracy 0.4 px); near the edges labels moved from about 35 px off to 0.5 px. The correction is only kept if it really improves the edges; otherwise the original solution stays. It takes about a second.

  • When: by default for solutions wider than 5° (camera lenses and phones). Telescope fields have hardly any distortion and are left as they are. Solutions already stored in a file are not changed.
  • The star catalogue: about 41,000 Hipparcos stars down to magnitude 8 are built in, which is plenty for phones and wide lenses. For longer lenses (50–135 mm), a deeper catalogue helps: choose the depth and press Update the star catalogue in Settings › Star catalogue and lens distortion. It downloads Tycho-2 from CDS VizieR in Strasbourg (to magnitude 8, 9 or 10: 1, 3 or 9 MB) and shows what is in use under the button. Use the built-in catalogue again removes the download. If a download fails, nothing changes.
  • Saved solutions (.wcs files and solutions written into FITS headers) include the distortion terms, so other programs that read SIP (PixInsight, Siril, ASTAP, astrometry.net tools) see the same corrected solution.

When an image won't solve

  • Processed JPGs and TIFFs usually contain no focal length or pixel size, so the scale is taken from Equipment. If the image was drizzled, binned, resized or cropped and resampled, or taken with other equipment, that scale is wrong. ASTAP then tries again with any image scale (between about 10° and 0.3° high), which is slower but finds it (ASTAP › If not solved, try again with any image scale). The Scale check line in the Solution tab then shows the real scale.
  • Check Equipment: a wrong focal length or pixel size sends the solver looking for the wrong field size.
  • Heavily processed, cropped or very small JPGs have fewer usable stars. Try the original FITS or PixInsight XISF, or enable astrometry.net.
  • Things in the image that aren't sky – menus and text in a photo of a screen, trees, buildings, empty stacking edges – can confuse the solver. Leave them out with Crop and rotate (C) and solve again.
  • Phone photos and other very wide-field photos: answer Yes when PlateSolver asks whether it is a phone photo, to try the phone and wide-field aids.
  • For ASTAP: make sure a star database is installed that suits your field size (D50 for most telescopes, W08/G05 for camera lenses, see Wide-field images).
  • Very short exposures or clouds: too few stars. More stars = easier solving.
  • The Log tab shows each solver's message, including ASTAP's own last lines (ASTAP said: …): how many stars it found in the image and in its database, and why it stopped.
  • If ASTAP finds plenty of stars in the image and in the database but still reports "No solution found" at every scale, the star pattern in the image has probably been changed by processing (strong star reduction, transforms or warping in an image editor). Solve the original stacked FITS, or let astrometry.net try.

8. The objects in your image

Where the objects come from

  • SIMBAD (online) is the main astronomical database, run by CDS in Strasbourg. PlateSolver asks it for everything with a well-known designation (Messier, NGC, IC, Sharpless, Barnard, named objects, …) plus bright stars and large objects in your field. It also provides parallaxes, published distances and redshifts. Results are remembered for two weeks, so reopening an image is fast and works offline.
  • OpenNGC (built in) contains all 13,000+ NGC, IC and Messier objects. By default it is used only when SIMBAD can't be reached, so you still get a list without internet. Some distances then still work (from its parallaxes and redshifts). Each new PlateSolver version comes with the newest OpenNGC release; the version in use is shown on its page in Settings › Object catalogues › OpenNGC.
  • HyperLeda (optional) adds faint galaxies, so background galaxies in deep images get names too (PGC, UGC, ESO, SDSS, 2MASX…). It reads ASTAP's HyperLeda database, hyperleda.csv (about 5 million galaxies, of which 2.2 million have a name). Install it with the HyperLeda installer from hnsky.org/astap.htm; PlateSolver finds it in the ASTAP folder or its Database/databases folder, or you can set the file in Settings › Object catalogues › HyperLeda. That settings page shows which file is used (✓ Found automatically: …) or, in red, that none was found. HyperLeda galaxies are only added for fields up to 15° (setting Only for fields up to), since faint galaxies can't be seen in wide-field and phone photos. The first time it is used, the file is indexed for fast lookups, which takes about half a minute (the Log says so); after that each image takes a fraction of a second. The brightest galaxies in the field come first, up to Maximum number of galaxies (50 by default). NGC and IC objects are left out, since the other catalogues have them. With an internet connection, SIMBAD is asked once for the type and redshift of all these galaxies, which gives most of them a distance.

When both catalogues are used, objects found in both are merged, so nothing is listed twice.

What is included (stars brighter than a magnitude, minimum sizes, maximum number of objects) is set in Settings › Object catalogues.

Visible stars first

The catalogues know far more objects than any one image shows. Many markers therefore sit on empty-looking sky: faint galaxies and nebulae that are really there, just too faint for this exposure. Meanwhile many stars you can see have no marker, because stars are only taken from the catalogues down to a brightness limit. PlateSolver can instead look at the image itself. This is on by default; change or switch it off in Settings › Visible stars and label order. Switched off, every object from the catalogues is marked and labelled the same way, without looking at the image.

When it is on, PlateSolver finds the stars in your image after solving, and then:

  • Checks every marked object. A star counts as visible when a star in the image sits on its position. A galaxy or nebula counts as visible when its centre is clearly brighter than the sky around it, with the stars masked out and gradients such as the Milky Way allowed for. A star cluster counts as visible when clearly more stars are bunched there than in the sky around it. Objects that fill most of the frame, and objects whose centre is outside the image, are left undecided: they are never dimmed or hidden.
  • Adds visible stars that had no marker, brightest first, up to the number you set (50 by default). They are named after their catalogue: a proper name such as Vega, otherwise the Bayer or Flamsteed name (α Lyr, 61 Cyg), HD, HIP or TYC number, with a distance from the star's parallax. Names and distances come from SIMBAD and need an internet connection. Without one, the stars are still marked, from PlateSolver's own star catalogue, as Star mag 4.2.
  • Labels the visible objects first (Label order: Visible objects first, then the best-known of the rest, the default). They get the space, and with Hide labels that would overlap on, the others may have to wait until you zoom in. Best-known objects first (Messier, named, largest, brightest), visible or not labels by catalogue data alone – Messier objects, objects with a common name, then the largest and brightest – but still marks visible objects and adds the unmarked stars.
  • Dims, shows or hides objects not visible in the image (Objects not visible in the image). Show them dimmed, so the visible objects stand out (the default) draws them faintly; Show them like the visible objects draws every object the same way; Hide them on the image, keep them in the object list leaves them off the image. They always stay in the object list.

In the object list, visible objects have a small green dot in front of their name, and the information card says In this image: visible or too faint to be seen. The filter panel's Visible in the image shows only what you can see. Changing these settings needs a new solve (F5), except the show/dim/hide choice, which applies at once.

The check is a judgement from the pixels, not a certainty. Very faint smudges near the noise may be called "too faint", and a bright patch of Milky Way at a nebula's position may count as visible. Phone photos work best with lens distortion correction on (the default), so the positions line up to the corners.

The information card

Point at an object on the image (or a row in the list) to see:

  • name and type,
  • distance with its uncertainty, and where the distance comes from,
  • apparent size (arc-minutes) and true size in light-years,

Light-travel and comoving distance

For nearby objects there is only one distance. For galaxies hundreds of millions of light-years away, the universe expanded while their light was on its way. "Distance" can then mean how far the light travelled (the light-travel distance, the default, as used in most popular writing) or how far away the galaxy is now (the comoving distance, which is larger). Choose in Redshift settings.

True size in light-years

An object's true size follows from its distance and how large it appears:

size = 2 × distance × tan(apparent size ÷ 2) ≈ distance × apparent size in radians.

Example: the Orion Nebula appears about 66′ across (1.1°) at 1,300 light-years, giving about 25 light-years. For distant galaxies the angular-diameter distance from cosmology is used, which is the correct distance for turning angles into sizes.

Sizes are approximate. A catalogued apparent size depends on how faint an edge was measured (for galaxies usually where the surface brightness drops to 25 mag/arcsec²), so deep images often show objects larger than the catalogue size.

When the light left

Light travels one light-year per year, so light from an object 1,300 light-years away left it about 1,300 years ago. PlateSolver turns this into a date ("around the year 720") or, for distant objects, a time ("about 2.5 million years ago"). For galaxies with redshift distances, the exact look-back time from cosmology is used.

11. Exporting and saving

Annotated image (File › Export annotated image, Ctrl+E)

Saves the picture with the overlays that are currently switched on, as PNG or JPEG. Labels and lines are scaled to the output size so they look the same as on screen. Object list (File › Export object list, Ctrl+Shift+E)

A CSV file with one row per object: names, type, coordinates, magnitude, apparent size, distance with uncertainty, method and source, true size, when the light left, and the Wikipedia and SIMBAD links. It opens in Excel or LibreOffice. With Swedish/European Excel settings choose semicolon with decimal comma in Export settings, so numbers land in separate columns.

Plate solution

  • File › Save plate solution (.wcs file) saves the solution as a small side-car file in the same format ASTAP and astrometry.net use, readable by most astronomy software.
  • File › Write plate solution into this FITS file stores it in the FITS file's own header (FITS only). The image data is not touched. The file then opens already solved, in PlateSolver and in other programs. Not available for a cropped or rotated view, whose solution doesn't fit the file's pixels.

12. Batch solving a folder

Tools › Batch solve folder (Ctrl+B) solves every image in a folder, for example a whole night's subs or your archive.

  1. Choose the folder, and whether to include subfolders.
  2. Choose what to save for each solved image:
    • a .wcs file next to it (on by default),
    • the solution written into the FITS header (off by default, because it changes your files),
    • an object list CSV per image (slower, since it looks the objects up online).
  3. Press Start. Each row shows the result: solved, already solved, failed or error, with the centre, scale and time taken.

FITS files that are already solved are not solved again, and no new files are written for them. The chosen options are remembered as the defaults (Batch settings).

19. Adding your own modules

Everything PlateSolver does is a module, so new features can be added without changing the program. A module is a Python class in a .py file placed in %APPDATA%\PlateSolver\plugins (or in platesolver/plugins/<type>/). It is found automatically at start-up, and its Settings page is generated from its settings_schema().

Base classMethod to writePurpose

Solversolve(image, ctx) → SolveResultA new plate solver

Example, a cross at the image centre:

from platesolver.core.interfaces import OverlayLayer
from platesolver.core.settings import SettingField, STR

class CentreMark(OverlayLayer):
    plugin_id = "centre_mark"
    name = "Centre mark"
    description = "A cross at the image centre."

    def settings_schema(self):
        return [SettingField("color", "Colour", STR, "#ff4040")]

    def render(self, painter, image, solution, objects):
        x, y, c = image.width / 2, image.height / 2, self.setting("color")
        painter.line(x - 30, y, x + 30, y, c)
        painter.line(x, y - 30, x, y + 30, c)

Pixel coordinates are (column, row) with row 0 at the top of the displayed image. solution.radec_to_pixel(ra, dec) and solution.pixel_to_radec(x, y) convert between pixels and sky coordinates. The README in the program folder describes the design in more detail.

  • Filter panel for the object list: a small funnel button next to the search box filters by magnitude, distance, size, type, catalogue and "show only" choices (Messier, named objects, classic catalogues). The funnel shows how many filters are on, the filter is remembered, and right-clicking an object offers Show only / Hide its type. See Search and filter.
  • The filter boxes take decimals with a point or a comma (9.5 or 9,5), whatever language Windows uses, and negative magnitudes.
  • The filter panel has a lighter background with high-contrast text, boxes and checkboxes.
